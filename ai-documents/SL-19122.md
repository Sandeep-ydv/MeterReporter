Plan: Gate Wells Usage to iOS 14+ While Keeping MeterReporter iOS 13
Background

MeterReporter must support iOS 13 as a module so it can be imported by apps targeting iOS 13.
However, its internal dependency Wells relies on iOS 14+ APIs, causing compile and linkage failures.

The goal is to remove all unconditional references to Wells while keeping the public API unchanged.

Goals

1. Set MeterReporter minimum deployment target = iOS 13
2. Ensure Wells code is never referenced on iOS 13 (compile or runtime)
3. Preserve existing MetricReporter behavior on iOS 14+
4. Avoid #available checks at call sites in consuming apps

Non-Goals
1. Supporting Wells functionality on iOS 13
2. Modifying the Wells package itself
3. Changing MeterReporter public API
